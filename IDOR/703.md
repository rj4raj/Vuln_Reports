### Title
Insecure Direct Object Reference (IDOR) in Appointment Details

### Vulnerability Type
Insecure Direct Object Reference (IDOR)

### summary
While testing the appointment functionality, I noticed that appointment details are accessed using an ID in the URL.
The application does not verify whether the requested appointment belongs to the logged-in user. By simply changing the appointment ID in the URL, I was able to view another user's appointment details.
This allows authenticated users to access appointment information that should only be visible to the owner of the appointment.

### Vulnerable Endpoint
`https://kzlabs.com/703.php?action=appointment&id=`

### Steps to Reproduce
1. Log in to the application.
2. Go to the invoice page. `https://kzlabs.com/703.php?action=appointments`
3. Observe the following URL: `https://kzlabs.com/703.php?action=appointment&id=4`
4. Change the value of the `id` parameter from: `4` to  `5`
5. Visit the modified URL: `https://kzlabs.com/703.php?action=appointment&id=5`
6. Observe that a different invoice is displayed.
7. The invoice contains different order information and amounts belonging to another user.

### Impact
An attacker can access appointment records belonging to other users by changing the ID value in the URL.
This may expose: Appointment information, User details, Booking information, Other sensitive data related to appointments

### Remediation
1. Verify that the requested invoice belongs to the logged-in user before displaying it.
2. Do not rely on user-supplied IDs alone for access control.
3. Implement proper authorisation checks on the server side for every request.
4. Return an error if a user attempts to access an invoice they do not own.
