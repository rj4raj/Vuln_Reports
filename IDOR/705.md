### Title
Insecure Direct Object Reference (IDOR) in Support Ticket Functionality

### Vulnerability Type
Insecure Direct Object Reference (IDOR)

### Summary  
While testing the support ticket functionality, I noticed that tickets are accessed using a numeric ID in the URL.
The application does not verify whether the requested ticket belongs to the logged-in user. By changing the ticket ID in the URL, I was able to access support tickets submitted by other users.
The exposed ticket contained sensitive customer information, including the user's name, email address, account type, ticket details, and banking-related requests.

### Vulnerable Endpoint
`https://kzlabs.com/705.php?action=ticket&id=`

### Steps to Reproduce
1. Log in to the application.
2. Go to the invoice page. `https://kzlabs.com/705.php?action=support`
3. Observe the following URL: `https://kzlabs.com/705.php?action=ticket&id=2`
4. Change the value of the `id` parameter from: `2` to  `3`
5. Visit the modified URL: `https://kzlabs.com/705.php?action=ticket&id=3`
6. Observe that a different invoice is displayed.
7. The invoice contains different order information and amounts belonging to another user.

### Impact
An attacker can access support tickets belonging to other users by changing the ticket ID in the URL.
This may expose: Customer names, Email addresses, Account information, Sensitive support conversations, Banking and financial requests.

### Remediation
1. Verify that the requested ticket belongs to the logged-in user before displaying it.
2. Do not rely on user-supplied IDs alone for access control.
3. Deny access when a user attempts to view another user's ticket.
4. Return an error if a user attempts to access an invoice they do not own.
