### Title
Insecure Direct Object Reference (IDOR) in Invoice View Functionality

### Vulnerability Type
Insecure Direct Object Reference (IDOR)

### Summary
While testing the invoice functionality, I noticed that invoices are accessed using a numeric `ID` in the URL.
The application does not verify whether the requested invoice belongs to the currently authenticated user. By simply changing the invoice ID in the URL, I was able to access another user's invoice and view their order details.
This allows any authenticated user to access invoices belonging to other users.

### Vulnerable Endpoint
`https://kzlabs.com/702.php?action=trip&id=`

### Steps to Reproduce
1. Log in to the application.
2. Go to the invoice page. `https://kzlabs.com/702.php?action=trips`
3. Observe the following URL: `https://kzlabs.com/702.php?action=order&id=38`
4. Change the value of the `id` parameter from: `38` to  `39`
5. Visit the modified URL: `https://kzlabs.com/702.php?action=order&id=38`
6. Observe that a different invoice is displayed.
7. The invoice contains different order information and amounts belonging to another user.

### Impact
An attacker can access invoices belonging to other users by changing the ID value in the URL.
This may expose: Trip information, Booking details, Travel-related data. 
An attacker could enumerate invoice IDs and access a large number of invoices belonging to other users.

### Remediation
1. Verify that the requested invoice belongs to the logged-in user before displaying it.
2. Do not rely on user-supplied IDs alone for access control.
3. Implement proper authorisation checks on the server side for every request.
4. Return an error if a user attempts to access an invoice they do not own.
