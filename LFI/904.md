## Title
Local File Inclusion (LFI) via `file` Parameter

## Vulnerability Type
Local File Inclusion (LFI)

## Summary
While testing the application, I noticed that images are loaded using the `file` parameter.
By checking the page source, I found the following URL:
`https://kzlabs.com/904.php?file=cat1.jpg`

This suggested that the application loads files based on user input. I intercepted the request in Burp Suite and tested different file path payloads using Intruder.
One of the payloads successfully returned the contents of a local server file (`/etc/passwd`), confirming that the application is vulnerable to Local File Inclusion (LFI).

## Vulnerable Endpoint
`https://kzlabs.com/904.php`

## Vulnerable Parameter
`file`

## Steps to Reproduce
1. Open:  https://kzlabs.com/904.php
2. Right-click and select View Page Source.
3. Notice that images are loaded using: `https://kzlabs.com/904.php?file=cat1.jpg`
4. Capture the request in Burp Suite.
5. Send the request to Burp Intruder.
6. Replace the filename with common LFI payloads and start the attack.
7. Observe that one of the payloads returns a **200 OK** response.
8. Open the response and verify that the contents of `/etc/passwd` are displayed.

## Payload Used
`../../../../etc/passwd`

## Impact
- An attacker can read files stored on the server.
- Sensitive information such as configuration files, credentials, and application secrets may be exposed.
- Information obtained from these files could be used to perform further attacks.

## Remediation
- Only allow specific files to be loaded.
- Block directory traversal patterns such as `../`.
- Validate user input before processing file requests.
- Prevent access to files outside the intended directory.
