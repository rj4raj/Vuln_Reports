# Server-Side Request Forgery (SSRF) via Add & Scan Link
## Vulnerability Type
Server-Side Request Forgery (SSRF)

## Summary
While testing the **Add & Scan Link** functionality, I noticed that the application accepts user-supplied URLs and fetches them from the server without proper validation.
By providing a local file URI (`http://0x7f000001`) instead of a normal service URL, I was able to make the server read one of its own internal files and return the contents in the response.
This confirms that the application is vulnerable to SSRF and allows access to local resources that should not be accessible to users.

## Vulnerable Endpoint
`https://kzlabs.com/605.php`
### Parameter
`service_url`

## Steps to Reproduce
1. Go to: `https://kzlabs.com/603.php`
2. Locate the Run Health Check section.
3. In the Service Endpoint URL field, enter: `http://0x7f000001`
4. Click Check Now.
5. Observe that the application processes the supplied URI and displays the contents of the server's `/etc/passwd` file.

## Payload Used
`http://0x7f000001`

## Impact
An attacker can make the server access files and resources that should not be publicly accessible.
This may expose sensitive information such as configuration files, credentials, or other internal data.

## Remediation
1. Only allow valid http:// and https:// URLs.
2. Block access to local files and internal resources.
3. Validate user-supplied URLs before processing them.
4. Restrict requests to trusted destinations only.****
