## Title
Server-Side Request Forgery (SSRF) Leading to Local File Read via Metadata URL

## Vulnerability Type
Server-Side Request Forgery (SSRF)

## Summary
The application allows users to provide a URL in the **Metadata URL** field and fetches the supplied resource from the server side.
By supplying a `file://` URI instead of a normal URL, the server reads a local file and returns its contents in the response. Using the payload `file:///etc/passwd`, I was able to access and view the server's local file, confirming the presence of an SSRF vulnerability.

## Vulnerable Endpoint
`https://kzlabs.com/607.php`

## Vulnerable Parameter
`metadata URL`

## Steps to Reproduce
1. Go to: `https://kzlabs.com/607.php`
2. Locate the Metadata URL input field.
3. Enter the following payload: `file:///etc/passwd`
4. Submit the request.
5. Observe that the application reads the local file and displays its contents in the response.

## Payload Used
`file:///etc/passwd`

## Impact

1. An attacker can read sensitive files stored on the server.
2. Internal configuration files, credentials, and application secrets may be exposed.
3. Information gathered from these files can be used to perform further attacks against the application.

### Remediation

1. Only allow `http://` and `https://` URLs.
2. Block dangerous schemes such as `file://`.
3. Validate and sanitize all user-supplied URLs before processing them.
4. Restrict server-side requests to trusted destinations only.
