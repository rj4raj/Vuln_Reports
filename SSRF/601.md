# Title
Server-Side Request Forgery (SSRF) via Webhook Test Endpoint

## Vulnerability Type
Server-Side Request Forgery (SSRF)

## Summary
The webhook testing feature allows users to enter a URL and have the server send a test request to it. However, the application does not properly validate the supplied URL.
By entering `file:///etc/passwd` instead of a normal webhook URL, I was able to make the server read its own local file and display the contents in the response. This confirms that the application is vulnerable to SSRF and allows access to internal server resources that should not be exposed.

## Vulnerable Parameter
Parameter:  `webhook_url`

## Steps to Reproduce
1. Navigate to: `https://kzlabs.com/601.php`
2. Open the Webhooks page.
3. In the Webhook Endpoint URL field, enter: `file:///etc/passwd`
4. Click Send Test Event.
5. Observe that the application fetches the file and displays its contents in the response section.

## Payload Used
`file:///etc/passwd`

## Impact
An attacker can:
- Read sensitive files stored on the server.
- Access configuration files that may contain database credentials, API keys, or other secrets.
- Gather information about the server environment.
- Access internal resources that should not be publicly available.

## Remediation
1. Only allow webhook URLs that use `http://` or `https://`.
2. Block dangerous protocols such as `file://`, `ftp://`, and `gopher://`.
3. Validate all user-supplied URLs before making requests.
4. Restrict access to local files and internal network resources.
